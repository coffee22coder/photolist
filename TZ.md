# ТЗ: PhotoList — шаг 4 (`4_xss_csrf`)

## Цель

У фотографии появляются комментарий и рейтинг. Рейтинг меняется кнопками на странице списка.

На этом шаге дыры остаются специально. Комментарий выводится как есть, голос принимается любым методом и без отдельного токена. Иначе XSS и CSRF на `localhost` не воспроизводятся.

Авторизация, argon2, cookie `session_id`, JPEG и превью не меняются. CSRF-токен, `HttpOnly`, `SameSite` и проверку `Referer` не делать.

## Что изменить

- В `photos` колонки `comment` и `rating`.
- Форма загрузки: поле комментария.
- `GET /photos/rate` и `POST /photos/rate`.
- Список фото рендерится через `text/template`. Логин и регистрация остаются на `html/template`.

`CREATE TABLE IF NOT EXISTS` уже существующую таблицу не расширит. Колонки добавляются отдельно, через `ALTER TABLE`.

## Задачи

### Таблица

`comment` — текст, может быть пустым. `rating` — целое, по умолчанию `0`.

Старые строки после `ALTER` получают `rating = 0` и пустой комментарий.

### Загрузка

Поле формы: `comment`, многострочный текст. Файл по-прежнему `my_file`, `enctype="multipart/form-data"`, `action="/photos/upload"`.

`comment` берётся через `FormValue` и пишется в ту же строку, что `user_id` и `path`. Пустой комментарий — нормальная загрузка.

После успеха редирект `302` на `/photos/`.

### Список

`GetPhotos` читает `id`, `user_id`, `path`, `comment`, `rating`.

На каждое фото:

- картинка `/images/{{.Path}}_160.jpg`;
- комментарий;
- кнопки «вверх» и «вниз»;
- число рейтинга в элементе с id `rating-` и id фото.

Кнопки не отправляют форму. Они вызывают JS, который делает `POST /photos/rate?id=<id>&vote=up` или `vote=down`.

Ответ сервера — JSON только с `id`. Новое значение рейтинга сервер не присылает. Страница сама прибавляет `+1` или `-1` к числу в `rating-<id>`.

### Голос

Маршрут `/photos/rate`, за авторизацией. Без сессии — `401`, как у остальных закрытых URL.

Параметры `id` и `vote` через `FormValue`, то есть и из query, и из тела.

| Вход | Результат |
|---|---|
| `vote=up` | `rating` в базе `+1` |
| `vote=down` | `rating` в базе `-1` |
| другой или пустой `vote` | `400`, тело `{"err": "bad vote"}` |
| `id` не число | `400`, тело `{"err": "bad id"}` |
| ошибка базы | `400`, тело `{"err": "db err"}` |
| успех | `200`, `Content-Type: application/json`, тело `{"id": 1}` |

SQL: `UPDATE photos SET rating = rating + ? WHERE id = ?`.

Владельца фото не проверять. Голос меняет строку по `id`, даже если фото чужое. Метод запроса не проверять: срабатывают и `GET`, и `POST`.

### Шаблоны

Страница списка — `text/template`. `{{.Comment}}` в нём не экранируется.

`html/template` для этого списка на этом шаге не использовать. Он превратит `<` в `&lt;`, и XSS не откроется.

Логин и регистрация остаются на `html/template`.

Cookie `session_id` без `HttpOnly`. Иначе `document.cookie` сессию не покажет.

### Как убедиться

**XSS.** Войти, загрузить фото с комментарием:

```text
<script>alert(document.cookie)</script>
```

Открыть `/photos/`. Ожидание: браузер показывает alert, в тексте есть `session_id`. Комментарий не отображается как безопасный текст.

**CSRF.** Запомнить `id` своего фото и текущий `rating`. Будучи залогиненным, открыть в той же браузерной сессии:

```text
http://localhost:8080/photos/rate?id=1&vote=up
```

Ожидание: `rating` в базе стал на 1 больше, хотя кнопки на странице никто не нажимал. Тот же эффект у страницы с тегом `<img src="http://localhost:8080/photos/rate?id=1&vote=up">`: браузер сам отправит cookie.

Без cookie `session_id` тот же URL отвечает `401`, рейтинг не меняется.

### Не делать

CSRF-токен в форме, запрет не-POST на `/photos/rate`, проверку `Referer`, `HttpOnly` и `SameSite` у cookie, экранирование комментария через `html/template`, проверку «голос только за своё фото». Это закрытие дыр, не этот шаг.

Тесты `Rate` не обязательны. Сигнатуры `Add` / `GetPhotos` поправить в существующих тестах, если они перестанут собираться из-за новых полей.
