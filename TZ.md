# ТЗ: PhotoList — шаг 1 (`1_storage`)

## Цель шага

Убрать прямое обращение обработчиков к глобальному слайсу.

- список фотографий лежит в отдельном хранилище в памяти процесса;
- HTTP-обработчики — методы структуры, у которой есть хранилище и уже разобранный шаблон;
- шаблон разбирается один раз при старте.

Сохранение JPEG, MD5 и три превью остаются как на шаге 0. После рестарта список пустой, файлы на диске остаются.

Без БД, без интерфейса хранилища, без авторизации, без тестов. `userID` по-прежнему заглушка `0`.

---

## Что меняется относительно шага 0

| Было на шаге 0 | Стало на шаге 1 |
| --- | --- |
| Обработчик сам читает слайс | `List` берёт записи через `GetPhotos` |
| `Path` перед шаблоном превращается в готовый URL | В шаблон уходит запись как есть, `Path` — MD5 |
| Шаблон разбирается на каждый запрос | Шаблон разбирается один раз при старте |
| Редирект на `/` | Редирект `302` на `/photos` |
| Функции `mainPage` / `upload` и глобальное хранилище | Методы `PhotolistHandler`, хранилище создаётся в `main` |

Галерея больше не проверяет файл на диске и не собирает URL сама. Адрес картинки собирает шаблон.

Отдельного маршрута `/photos` нет. Список зарегистрирован на `/`. В `net/http` шаблон `/` забирает и все остальные пути, включая `/photos`. Поэтому после редиректа открывается та же страница, что и главная.

---

## Стек и ограничения

| Пункт | Требование |
| --- | --- |
| Язык | Go, модуль `photolist`, один пакет `main` |
| HTTP | `net/http`, без Gin |
| Порт | `:8080` |
| Картинки | как на шаге 0: JPEG, MD5 содержимого, превью 80 / 160 / 320 |
| Хранилище списка | память процесса, тип `StMem` |
| Шаблон | разобрать при старте, в `Execute` отдавать готовый `*template.Template` |

**Не делать на этом шаге:** MySQL, интерфейс хранилища, сессии, JWT, юнит-тесты, оптимизацию «открыть JPEG один раз». Повторное чтение файла на каждый размер превью остаётся.

Создание каталога `./images` при старте можно оставить.

## Модель и хранилище

```go
type Photo struct {
    ID     int
    UserID int
    Path   string // MD5, 32 hex-символа, без каталога и расширения
}

type StMem struct {
    items []*Photo
}

func NewStorage() *StMem
func (st *StMem) Add(p *Photo) error
func (st *StMem) GetPhotos(userID int) ([]*Photo, error)
```

`NewStorage` возвращает пустой список.

`Add` дописывает указатель в конец и возвращает `nil`.

`GetPhotos` принимает `userID`, но не фильтрует: возвращает все записи в порядке добавления и `nil`. Аргумент — задел на пользователей, на этом шаге он ни на что не влияет.

`ID` можно не заполнять. Порядок задаёт слайс. В запись кладётся `UserID: 0` и `Path: md5Sum`.

Поле `items` с маленькой буквы. Обработчик ходит в хранилище только через `Add` и `GetPhotos`.

Оба метода возвращают `error`, хотя память его не создаёт. Проверка ошибки в обработчике обязательна: позже на это место встанет другая реализация.

---

## Обработчик

```go
type PhotolistHandler struct {
    St   *StMem
    Tmpl *template.Template
}
```

В `main` один раз:

1. `NewStorage()`.
2. Разбор шаблона.
3. Указатель на `PhotolistHandler` с этими двумя полями.
4. `HandleFunc("/", h.List)` и `HandleFunc("/upload", h.Upload)`.
5. Статика: `StripPrefix("/images/", FileServer(Dir("./images")))`.
6. В stdout строка о старте. `ListenAndServe(":8080", ...)`.

Глобального слайса больше нет. Глобальным остаётся только `userID = 0`.

---

## HTTP API

### 1. `List` — `GET /`

Тот же обработчик отвечает и на `GET /photos`: отдельный маршрут не регистрируется.

**Алгоритм:**

1. `items, err := h.St.GetPhotos(userID)`.
2. Ошибка: лог `cant get items`, ответ `500`, тело `storage error`.
3. `h.Tmpl.Execute` с данными:

```go
struct {
    Items []*Photo
}{
    items,
}
```

4. Ошибка шаблона: лог `cant execute template`, ответ `500`, тело `template error`.

Диск в `List` не читается. Какая запись есть в хранилище, такая и попадает в HTML.

**Шаблон.** Поле данных — `Items`:

```html
<form action="/upload" method="post" enctype="multipart/form-data">
    <input type="file" name="my_file">
    <input type="submit" value="Upload">
</form>
{{range .Items}}
    <img src="/images/{{.Path}}_160.jpg" />
{{end}}
```

Разбор шаблона — при старте. `template.Must` при битой разметке роняет процесс до `ListenAndServe`, а не на первом запросе.

### 2. `Upload` — `POST /upload`

**Вход:** multipart, файл `my_file`.

**Алгоритм:**

1. `FormFile("my_file")`. Ошибка: лог `cant parse file`, `500`, тело `request error`.
2. Сохранить файл, получить `md5Sum`. Ошибка: лог `cant save file`, `500`, тело `Internal error`. В хранилище не писать.
3. Превью для `./images/{md5Sum}.jpg`. Ошибка: лог `cant resize file`, `500`, тело `Internal error`. В хранилище не писать.
4. `h.St.Add(&Photo{UserID: userID, Path: md5Sum})`. Ошибка: лог `cant store item`, `500`, тело `storage error`.
5. Успех: `302` на `/photos`.

### 3. `GET /images/*`

Без изменений шага 0: `StripPrefix("/images/")` + `http.FileServer(http.Dir("./images"))`.

Файл `./images/abc123....jpg` открывается по URL `/images/abc123....jpg`.

---

## Файловый контракт

Не меняется.

| Что | Контракт |
| --- | --- |
| Каталог | `./images/` |
| Оригинал | `{md5}.jpg`, MD5 содержимого, 32 hex-символа |
| Превью | `{md5}_80.jpg`, `{md5}_160.jpg`, `{md5}_320.jpg` |
| Ресайз | ширина = size, высота 0, фильтр Lanczos3 |
| Главная | только `_160.jpg`, размер выбирает шаблон |

Функции шага 0 остаются: `SaveFile(io.Reader) (string, error)`, `MakeThumbnails`, `ResizeImage`.

---

## Точка входа

- Зарегистрировать `/`, `/upload`, `/images/`.
- Хранилище и шаблон создать до `ListenAndServe`.
- В stdout: `starting server at :8080` (или уже существующая строка о старте).
- Порт `:8080`.

Запуск: из каталога проекта `go run .`.

---

## Входные и выходные данные

**Upload:** multipart, поле `my_file` = JPEG 800×600, MD5 содержимого `759bd21fabcd759bd21fabcd759bd21f`.

**После успеха:**

```text
хранилище: [{ID: 0, UserID: 0, Path: "759bd21fabcd759bd21fabcd759bd21f"}]
ответ:     302 Location: /photos
HTML:      src="/images/759bd21fabcd759bd21fabcd759bd21f_160.jpg"
```

**`GetPhotos(0)`** при двух загрузках одного и того же файла:

```text
[
  {ID: 0, UserID: 0, Path: "759bd21fabcd759bd21fabcd759bd21f"},
  {ID: 0, UserID: 0, Path: "759bd21fabcd759bd21fabcd759bd21f"},
]
```

На странице два `<img>` с одним и тем же `src`. На диске один набор файлов.

---

## Критерии приёмки

1. Старт с пустым хранилищем: `GET /` — форма, без картинок.
2. `GET /photos` показывает ту же страницу, что и `GET /`.
3. JPEG → `302` и `Location: /photos`. На странице `<img src="/images/{md5}_160.jpg">`.
4. Два разных файла — две записи, порядок как у `Add`.
5. Тот же файл дважды — один набор файлов на диске, в хранилище две записи с одним `Path`, на странице два `img`.
6. Битый файл или ошибка превью — `500`, в хранилище пусто.
7. Рестарт процесса — список пустой, файлы в `./images` на месте.
8. Шаблон не разбирается заново на каждый `GET /`.

---

## С чего начать в текущем коде

`Path` в слайсе уже MD5. Это подходящий вход для `Add`.

Дальше три замены:

1. Методы `Add` и `GetPhotos` вместо прямого доступа к слайсу.
2. Шаблон с `Items` и `/images/{{.Path}}_160.jpg` вместо готового URL.
3. Редирект на `/photos` со статусом `302`.

Подмену `Path` на `/images/..._160.jpg` и `os.Stat` превью в список переносить не нужно.

---

## Что будет дальше

Интерфейс хранилища и другая реализация вместо `StMem` на этом шаге не нужны. `error` у `Add` и `GetPhotos` и аргумент `userID` оставлены как шов под этот следующий шаг.
