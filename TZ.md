# ТЗ: PhotoList — шаг 0 (`0_basic`)

## Цель шага

Минимальный **монолитный** веб-сервис:

- загрузить JPEG;
- сохранить на диск;
- сделать превью;
- показать список на главной.

Без БД, без авторизации, без тестов. Данные только **в памяти процесса** (после рестарта список пустой, файлы на диске остаются).

---

## Стек и ограничения


| Пункт            | Требование                                       |
| ---------------- | ------------------------------------------------ |
| Язык             | Go, модуль `photolist` (или свой module path)    |
| HTTP             | `net/http`, без Gin/Mux                          |
| Порт             | `:8080`                                          |
| Картинки         | только **JPEG** (decode через `image/jpeg`)      |
| Ресайз           | `github.com/nfnt/resize`                         |
| Хранилище файлов | каталог `./images/` относительно cwd при запуске |


**Не делать на этом шаге:** MySQL, сессии, JWT, шаблоны в отдельном пакете, юнит-тесты, рефакторинг «на будущее». Комментарии в эталоне про «проблемы» — задел на шаги 1+; на шаге 0 их **можно оставить как есть**.

---

## Модель данных (in-memory)

```go
type Photo struct {
    ID     int   // уникальный в рамках процесса, с 1 или 0 — главное стабильно и по порядку добавления
    UserID int   // всегда 0 (заглушка «один пользователь»)
    Path   string // MD5 hex оригинала, без расширения; файлы: {Path}.jpg, {Path}_80.jpg и т.д.
}
```

Глобальный (или package-level) слайс `[]*Photo` — **допустимо** на шаге 0.

## HTTP API

### 1. `GET /`

**Назначение:** HTML-страница: форма загрузки + галерея.**Форма:**

- `method="post"`, `action="/upload"`, `enctype="multipart/form-data"`
- поле файла: `name="my_file"`
- кнопка submit (текст на твоё усмотрение)

**Галерея:**

- для каждого `Photo` из in-memory списка — `<img src="/images/{{Path}}_160.jpg">`
- порядок: как в слайсе (обычно порядок загрузки)

**Ошибки шаблона:** лог + `500`, тело вроде `template error`.

### 2. `POST /upload`

**Вход:** multipart, файл `my_file`.

**Алгоритм:**

1. Прочитать файл из формы; ошибка парсинга → лог + `500` `Internal error`.
2. Сохранить оригинал → получить `md5Sum` (см. файловый контракт).
3. Сгенерировать превью для `md5Sum`.
4. Добавить запись в in-memory список (`UserID = 0`, `Path = md5Sum`).
5. `**302 Redirect` на `/`** (не JSON, не 200 с телом).

Любая ошибка save/resize → лог + `500`, запись в список **не** добавлять.

### 3. `GET /images/*`

**Назначение:** отдача статики из `./images/`.

**Паттерн:** prefix `/images/` + `http.FileServer(http.Dir("./images/"))` + `StripPrefix`.

**Пример:** файл `./images/abc123....jpg` → URL `/images/abc123....jpg`.

## Файловый контракт (диск)

**Каталог:** `./images/` — создать при необходимости (или документировать «создай руками перед первым upload»).

**Имя оригинала:** `{md5_hex}.jpg`, где `md5_hex` — MD5 **содержимого** файла (32 hex-символа).

**Рекомендуемый алгоритм save** (как в курсе):

1. Временное имя (случайная строка) → `./images/{tmp}.jpg`.
2. Писать поток в файл и одновременно считать MD5 (`io.TeeReader`).
3. `Sync`, закрыть.
4. `Rename` temp → `./images/{md5}.jpg`.

Так не перетираешь чужой файл при коллизии имён до подсчёта хеша.

**Превью:** для каждого `size` из `**80, 160, 320`**:

- путь: `./images/{md5}_{size}.jpg`
- ресайз: ширина = `size`, высота **0** (пропорции), фильтр Lanczos3
- исходник для всех трёх — один и тот же `{md5}.jpg`

**Главная страница** использует только `**_160.jpg`**.

## Критерии приёмки (ручная проверка)

1. **Пустой старт:** `GET /` — форма, без картинок (или пустой список).
2. **Upload:** валидный `.jpg` → редирект на `/`, на странице новая картинка.
3. **Файлы на диске:** `{md5}.jpg`, `{md5}_80.jpg`, `{md5}_160.jpg`, `{md5}_320.jpg`.
4. **Прямой URL:** `/images/{md5}_160.jpg` открывается в браузере.
5. **Два upload подряд:** две записи в списке, два набора файлов.
6. **Один и тот же файл дважды:** тот же `md5` → те же имена на диске; в памяти **две** записи с одним `Path` (на шаге 0 так ок).
7. **Не-JPEG / битый файл:** `500` на upload, без паники.
8. **Рестарт процесса:** список пустой, старые файлы в `./images/` остаются (ожидаемо).

## Входные / выходные данные (пример)

**Upload:** multipart, поле `my_file` = JPEG 800×600.

**После успеха:**

- Redirect `302` → `Location: /`
- На диске, например: `759bd21f...jpg` + `_80`, `_160`, `_320`
- In-memory: `{ ID: 1, UserID: 0, Path: "759bd21f..." }`

**GET /:** HTML с `src="/images/759bd21f..._160.jpg"`.
